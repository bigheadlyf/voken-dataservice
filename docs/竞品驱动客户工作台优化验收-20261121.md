# 竞品驱动的客户工作台优化

日期：2026-11-21（香港时间）。本轮根据来发信、TradeWind 样本测试实施代码与本地隔离验收，不迁移当前业务数据库，不改写已有客户、联系人、历史任务或跟进活动。

## 已实现

| 优化项 | 交付行为 | 边界 |
| --- | --- | --- |
| 联系人补全 | 工作台选企业 → 核对供应商主体 → 目标岗位查询 → 保存无邮箱岗位候选／按需单主体解锁 → 保存独立候选 | 复用现有跨境魔方预算、付费确认与缓存；未新增另一家联系人数据库，实际覆盖仍取决于供应商 |
| 企业／岗位／邮箱三项判断 | 企业人工评审、原文岗位关键词匹配、独立验证分开展示；保留证据完整度原有含义 | 关键词匹配不等于任职及采购职责已经确认 |
| 独立邮箱验证 | ZeroBounce v2 单邮箱适配、明确确认、空间绑定、日上限、请求幂等、追加验证历史；valid/invalid/catch-all/unknown 分开，超过30天标记需重查 | 默认未配置，不发出请求；使用验证商额度，不计入现有平台点数。异常不自动重试，需先核对上游消费。有效不保证送达 |
| 企业和联系人双视图 | 国家、阶段、标签、邮箱、岗位判断、到期筛选；保存视图；企业已评审、岗位匹配、邮箱近期有效的联合筛选 | 展示去重不删除原始记录；档案总数不冒充去重企业总数 |
| 重复与噪声提示 | 同地区相近名称／相同官网域名提示关联；招聘、服务质量、邮箱格式示例、跨域关系未确认单独提示 | 不自动合并；集团、分支、别名须人工核对 |
| 预览与反馈 | 独立多产品档案、AI客群方向假设、选定方向预填小批量预览；结构化反馈原因，影响下一次相同画像 | 不更新原企业资料，不创建任务直到用户提交；历史任务及旧反馈不重写 |
| 跟进与回复闭环 | 批量多步骤提醒、到期列表、完成标记；追加回复、退信、拒绝联系和会议事件；EML预览归档，配置后只读IMAP同步 | 不自动群发；新退信／拒绝联系事件在草稿、提交及SMTP执行前拦截；原客户阶段、主邮箱、旧跟进日期保持原样 |
| 名单导入 | CSV/XLSX/文字型表格PDF，字段映射、前10行样本、来源年份、逐行错误、幂等确认导入 | 每批200行、5MiB；拒绝公式；PDF需表头和制表符或竖线分列，不支持扫描OCR和任意版式。已有同名同地区客户原样复用 |
| 周期增量 | 任务详情只读比较相同员工和画像的历史结果，分别显示首次出现企业、新增邮箱和历史已出现 | 规范化名称和地区比较，别名可能分开；变化不等于当前采购需求 |

## 数据保护方式

新增表 `crm_workspace_records` 保存追加式候选、评审、验证、产品、视图、联系事件、提醒和导入预览。迁移 `0015` 只建新表和索引，没有旧业务表 UPDATE、DELETE、回填或合并。

新页面保存联系人走 `/crm/workbench/candidates`，不再走旧的自动填充主邮箱流程；既有 API 保留兼容行为。用户明确确认名单导入时，仅新增客户；重复项复用原档案，不覆盖原字段。新联系事件不会写入原 `crm_activities` 或修改 `crm_prospects`。

退信／拒绝联系属于新增的发送约束，不修改旧客户字段；同邮箱后续邮件同样被拦截。不会自动取消、重写过去的发送记录。

## 配置和启用

1. 在目标运行环境安装 `requirements.txt`（新增 openpyxl），先备份数据库，再执行 `python -m alembic upgrade head`，重启常驻服务。业务前端入口 `/app#workbench`。本轮未对现有开发库或生产库执行此步骤。
2. 独立验证：`EMAIL_VALIDATION_API_KEY`、`EMAIL_VALIDATION_WORKSPACE_ID`、`EMAIL_VALIDATION_DAILY_LIMIT`。默认日上限20次；必须显式绑定一个工作空间。前端每次验证都需用户勾选额度消耗确认。没有配置时不回退到模拟有效结果。
3. 收件同步：`IMAP_HOST`、`IMAP_USERNAME`、`IMAP_PASSWORD`、`IMAP_WORKSPACE_ID`，固定TLS 993，仅手动同步 INBOX 最近20封；先查大小，最多2MiB/封；使用只读 SELECT 和 BODY.PEEK，不改变远端已读状态。不会自动将邮件判为询盘或拒绝联系，必须核对归档。
4. 验证商、IMAP及更广联系人数据覆盖仍需真实配置与独立验收；本轮没有调用真实邮箱验证、连接真实收件箱、发送邮件或购买数据。

验证状态依据 [ZeroBounce v2 官方接口](https://www.zerobounce.net/docs/email-validation-api-quickstart/v2-validate-emails) 和 [状态说明](https://www.zerobounce.net/docs/email-validation-api-quickstart/v2-status-codes) 实现；catch-all不归为valid。

## 接口

统一前缀 `/api/v1/workspaces/{workspace_id}/crm/workbench`，Bearer鉴权与空间隔离。完整请求例子、响应模型在运行时 `/openapi.json`。

| 接口 | 用途 |
| --- | --- |
| GET 空路径 | 企业／联系人筛选投影及各项独立计数 |
| POST `/candidates`、`/people-candidates` | 追加解锁结果或无邮箱岗位候选 |
| POST `/assessments`，GET `/history/{prospect_id}` | 企业评审及独立历史 |
| GET/POST `/views`、`/products` | 筛选视图与多产品档案 |
| POST `/cohorts` | 产品、市场对应的客群方向假设 |
| GET `/capabilities`，POST `/verifications` | 配置状态与独立邮箱验证 |
| GET/POST `/followups`，POST `/followups/{task_id}/complete` | 提醒序列、执行状态与完成标记 |
| POST `/events` | 追加回复、退信、拒绝联系等事件 |
| POST `/imports/preview`、`/imports/commit` | 名单解析、映射与确认导入 |
| GET `/inbox`，POST `/inbox/preview`、`/inbox/archive`、`/inbox/sync` | 收件预览、归档与可选同步 |
| POST `/preview-feedback`，GET `/preview-feedback/{job_id}` | 结构化反馈历史的最新投影 |
| GET `/discovery-delta/{job_id}` | 同画像任务增量对比 |

`verifications`、`events`、`followups` 必须携带 `Idempotency-Key`。不确定的已提交验证不自动重发。导入确认以预览ID幂等，不同内容不能覆盖已经确认的预览。

## 验收

测试使用独立临时数据库与供应商形状的模拟响应，检验数据保护和流程，不将模拟响应算作真实联系人覆盖或验证能力。浏览器验收为独立 `127.0.0.1:18086` 临时服务，未使用原业务账号、客户或任务进行写入测试。

自动化覆盖：候选保存及重放、旧档案不变、空间隔离、邮箱验证状态／历史／幂等／日上限、供应商错误与邮箱错配、同一联系人联合筛选、退信前SMTP拦截、回复停止提醒、名单映射与重复原样复用、XLSX公式拒绝、EML确认归档、IMAP只读与去重、客群不创建任务、结构化反馈不改写快照、无邮箱岗位候选与增量比较。

完整回归164项通过（184.778秒）；最后补充的CSV超长单元格、归档邮箱格式、同一联系人联合筛选边界由17项专项复测覆盖。两组前端检查通过，浏览器确认视图保存、联系人切换、回复事件保存与联合筛选空状态；390px视口下文档宽度375px、内容宽度375px，无横向溢出。

迁移另在临时SQLite库中从0014升级0015，逐表比较30张旧业务表，内容完全一致；客户阶段与版本不变、新表为空。MySQL离线SQL也仅创建新表、索引并更新Alembic版本号。

证据：`.local/workbench-regression-verified-20261121.log`、`.local/workbench-targeted-verified.log`、`.local/workbench-migration-verification.json`、`.local/workbench-migration-0015.sql`、`.local/workbench-ui-20261121.png`。本轮均为隔离测试，没有据此声称真实邮箱或采购联系人覆盖率提升。
