# 微元 1.0 拓客能力设计

设计评审稿 · 2026-11-16

## 1. 首版交付

首版默认交付**基于公域证据的潜在客户清单**。用户提交品类、市场和时间窗口，智能体从企业官网、行业目录、展会名录、公开招标等来源发现企业，提供主体、产品匹配理由、公开联系方式和可追溯来源。普通拓客默认零次付费商业数据调用。需要证明进出口交易、供应商与买家关系或获取正式信用报告时，按需核验并单独计量。

| 场景 | 怎么查 | 交付优先级 |
| --- | --- | --- |
| 按产品或行业找潜在客户 | 从官网产品目录、协会或展会名录、经销商列表和采购公告发现企业，按产品、角色和目标市场去重排序。 | 1.0 主流程 |
| 找明确的采购需求 | 查公开招标及采购公告，提取采购主体、品类、公告状态和截止日。 | 1.0，按目标市场覆盖 |
| 从已知供应商找买家 | 查供应商公开的客户案例、合作公告及授权渠道，按原文展示关系类型。用户需要验证历史交易时再按供应商和品类查海关。 | 1.0，按需核验 |
| 按贸易条件找已核实买家 | 使用用户明确选择的增强检索，按 HS、贸易时间和起运或抵运口径查询授权贸易记录。 | 1.0，受套餐与预算限制 |
| 查企业与目标市场动态 | 对候选企业、地区或国家发起公域在线搜索，找近期公告、新闻和政策更新，用于确认跟进时机和识别市场变化。 | 1.0 按需查询，可用于拓客任务和情报报告 |

增强检索接口依据见[跨境魔方 OpenAPI 总览](https://developer.upkuajing.com/openapi/)和[采购商与供应商列表参数](https://raw.githubusercontent.com/Upkuajing/upkuajing-trade-company-search/main/references/company-list-api.md)。

## 2. 从用户需求到可跟进线索

以“找美国的某类产品经销商，优先有采购信号的企业”为例。智能体先用当地语言产品词及同义词、企业角色和地区，查经销商名录、协会或展会目录、采购公告和本地企业官网。搜到线索后，优先回到官网核实企业、产品、市场和公开联系方式，并保留证据链接。

### 2.1 公域发现与补全

| 原付费步骤 | 默认公域替代 | 证据及覆盖边界 |
| --- | --- | --- |
| 公司列表、地图商户搜索 | 企业产品目录、协会会员目录、展会名录、品牌的授权经销商页及公开招标。优先使用可直接检索或批量复用的来源。 | 展会参展仅证明出现在参展名单中。需要从官网确认角色和产品，公开招标注明公告阶段和截止日。 |
| 公司详情 | 企业官网、官方企业登记、上市公司披露。 | 展示可验证的主体、注册编号和状态。缺失字段保留为空。 |
| 联系方式 | 官网 Contact 页、商务询盘入口、公司公开邮箱或总机。 | 保存网址与获取时间，按官方来源展示联系方式。联系渠道和可达状态分别记录。 |
| 国家、品类贸易趋势 | 官方开放的贸易统计，按品类、国家和时期查询。 | 作为市场研判背景。企业级进出口事实需要能对应到该企业的交易记录。 |
| 信用报告 | 官方登记及其他可引用的公开披露，用于基础背景核验。 | 正式信用报告由独立来源按需供给。 |

可用来源示例包括欧盟 TED 的公开采购公告、英国 Companies House 的企业登记，以及美国 Census 的按商品和国家汇总的贸易统计。实际接入按目标市场、覆盖范围和复用条款选择。[TED Search API](https://docs.ted.europa.eu/api/latest/search.html) · [Companies House 接入说明](https://developer.company-information.service.gov.uk/get-started) · [美国 Census 贸易数据说明](https://www.census.gov/foreign-trade/reference/guides/Guide_to_International_Trade_Datasets.pdf)

排序优先看主体与角色是否明确、目标产品和市场是否匹配，以及采购公告、渠道扩张等信号是否可核验、仍具时效。线索卡区分“产品或渠道匹配”“公开采购信号”“已核验海关交易”，同一家企业可同时拥有多种证据。公域覆盖不足时返回有限结果并说明已查范围。

### 2.2 按需核验交易

当用户要求“近 12 个月从中国发货到美国的买家”或需要证明特定供货关系时，先复用仍有效且有权访问的贸易证据，再按已选核验范围、套餐权益和预算查询。已有明确企业身份时直接按企业、品类、时间和路线查交易明细，避免先购买列表再逐家补查。需要由贸易记录反查买家时，从一页采购商列表或一页贸易记录起步，再按剩余预算续查。采购商所属国、起运国、抵运国和生产国使用各自口径，六位 HS 编码无法区分细分品类时结合商品描述核验。海关无命中时保留已有公域线索并注明交易核验结果。[采购商列表参数](https://raw.githubusercontent.com/Upkuajing/upkuajing-trade-company-search/main/references/company-list-api.md) · [贸易列表参数](https://raw.githubusercontent.com/Upkuajing/upkuajing-trade-company-search/main/references/trade-list-api.md)

### 2.3 公域实时搜索

首版提供两个入口。用户可以独立查询某家企业、一个地区或国家的最新公开动态，也可以从拓客线索卡刷新指定企业。实例可选择在运行时查目标市场，并为排名靠前的少量企业补充动态。公域检索使用独立的调用预算。实时指用户触发时发起在线检索，结果标注检索截至时间和可见的原文发布时间。定期监测和推送留作后续产品决策。

网页发现统一使用 DeepSeek Search。通过企业名称、产品词、地区及语言缩小范围，必要时用 `site:` 限定企业或主管机关官网，再结合 `after:`、`before:` 对报道的发布时间筛选。正文已有可用内容时直接复用，待核验的重点来源再用 DeepSeek Fetch 读取。[DeepSeek 网页搜索与抓取](https://api-docs.deepseek.com/zh-cn/guides/search/)

| 查询范围 | 重点查什么 | 如何用于拓客 |
| --- | --- | --- |
| 企业 | 官网公告、投资者关系、公开招标、新闻报道中的扩产、设仓、新品或渠道扩张。 | 例如既有匹配的采购记录，又出现可核验的仓储扩张公告，可提示业务员核实新增采购计划。扩仓及其潜在影响分别展示。 |
| 地区 | 地方政府、港口与行业组织发布的产业项目、园区招商、招标和物流动态。 | 给区域拓客补充渠道或到货风险线索。签约、开工和投产分别标明，避免把计划误判为已发生。 |
| 国家或政策辖区 | 主管机关、海关及公报发布的关税、进出口限制、认证、标签和标准变化。 | 关联目标市场、产品描述或对应编码，提示受影响范围和关键日期。适用性无法确认时，标记为待核验。 |

示例来源包括可查找卫生与植物卫生措施及技术性贸易壁垒通报的 WTO ePing，以及可查找美国联邦拟议规则、最终规则和公告的 Federal Register。政策状态和适用范围以相关发布机关的原文及修订公告核验。[WTO ePing 数据说明](https://data.wto.org/dataset/ext_eping) · [美国国家档案馆 Federal Register 说明](https://www.archives.gov/federal-register/the-federal-register)

### 2.4 检索、核验与落库

1. **生成查询。** 将企业正式名称、别名、官网域名和国家，或目标地区、产品、主题和时间窗口转为查询参数。优先使用目标市场的当地语言和常用英文名，保留实际检索条件。对同名企业结合官网、注册地址和公告主体核验。
2. **找原文并合并重复报道。** 用 DeepSeek Search 的标题、摘要及链接选出证据候选，优先核对企业官网、主管机关、监管机构或官方公报原文。按原文 URL、公告文号或同一事件聚合转载。无法打开原文或只看到搜索摘要时保留为待核验线索。分别记录原文发布时间、更新日期、事件发生时间和检索时间。
3. **提取事实与影响。** 保存标题、来源机构、原文链接、主题、关联企业或地区、适用产品和日期字段。政策额外记录可核实的法规状态、适用辖区、产品范围、发布日、生效日和修订关系。政策按版本保存，原文有修订时关联前后版本。公域信号可解释跟进时机或市场影响，交易核验仍以匹配的贸易证据为准。
4. **保存并复用结果。** 在授权范围内持久化来源元数据、摘要、实体关联及检索时间。市场动态可按地区、主题、产品和时间窗在同次任务内复用，企业动态按已确认实体复用。依照来源授权和工作空间权限决定缓存的共享范围。搜索不可用时可展示带历史时间戳的合规缓存。有结果但可信度不足、检索无匹配和检索失败分别反馈。

## 3. 多实例和服务端边界

- **数字员工**保存自己的产品词、市场、时间窗口、指定供应商、排除规则和预算。同一工作空间可建立多个数字员工，并分别编辑、启动、暂停或删除。新员工默认暂停，启动提交一次运行，运行记录保存配置版本和实际查询条件。暂停或删除时在后台任务步骤边界停止后续查询，保留已生成的结果。
- **智能体编排**负责把需求转成结构化参数、解释命中证据和生成待核验事项。**服务端**负责参数校验、分页、金额上限、去重、来源标识、权限和订阅计量。由服务端统一控制付费调用，避免模型在关键词扩展或翻页时无限调用。
- **数据模型**保留企业档案、来源企业标识、贸易证据以及任务到线索的关联。海关、企业库和地图的公司 ID 分开命名，跨库匹配优先用可核实的注册标识，辅以国家、名称、官网和地址。多家主体共用官网或名称相近时标为待确认。原始响应、交易引用和联系方式按供应商授权存储、访问和刷新。
- **任务执行**记录每个查询的接口、参数、分页位置、成功状态和成本估算。任务重跑优先复用合规且仍有效的结果。已确认完成的页可续跑。遇到请求超时且扣费结果未知时记为待核对，按供应商的幂等或账单能力决定是否重试。超限、数据覆盖不足与查询完成但无命中使用不同状态。

## 4. API 费用和订阅用量

| 运行示例 | 跨境魔方付费调用 | 供应商费用试算 |
| --- | --- | --- |
| 原方案，查 2 页候选并为 5 家逐一查贸易、详情和联系方式 | 17 次 | 18 元 |
| 公域拓客，官网和登记信息补全 | 0 次 | 0 元 |
| 公域筛选后，按需核验 1–2 家，每家查 1 页贸易明细 | 1–2 次 | 1.5–3 元 |

试算按公开价目中的列表和贸易明细 1.5 元/次、公司详情 1 元/次、联系方式 0.5 元/次计算。核验示例假定已有可直接查询的企业标识或名称，每家一页足以取证。费用仅包含表中跨境魔方调用。公域搜索、网页读取、模型、存储及独立信用报告另计。合同价、翻页、批量和重试的实际计费需对账确认。[跨境魔方 OpenAPI 公开价目](https://developer.upkuajing.com/openapi/)

服务端执行以下成本规则。

- 普通拓客和基础情报报告的付费商业数据预算默认为 0。用户明确选择增强核验后，展示核验范围和预算上限，先查授权缓存，再在剩余额度内调用。付费额度不足、来源超时或公域结果少时，返回已有结果和覆盖说明。
- 独立记录 DeepSeek Search、Fetch、商业数据核验和用户订阅用量。按公开价，5 次搜索返回结果、3 次抓取返回正文，共 **0.04 元**，模型费用单列。优先复用仍有效且获准使用的原文。每次任务限制搜索数、抓取数和处理时间。费用以账号账单为准。[DeepSeek 工具计费](https://api-docs.deepseek.com/zh-cn/guides/search/#计费)
- 并发核验在调用前占用预算，避免多实例透支。对等价请求复用在途任务和已确认结果。供应商扣费未知时保留待核对状态，按已确认规则结算用户用量。

## 5. 首版验证

真实拓客输入、证据要求及注册送点测试见[《微元 1.0 首批验收用例》](./微元1.0首批验收用例.md)。

| 验证项 | 通过条件 |
| --- | --- |
| 市场口径与商品匹配 | 分别提交只限抵运国和只限采购商所属国的任务，查询参数、线索展示和交易证据遵守对应口径。六位 HS 划入多个品类时，利用产品描述核验，歧义结果可识别。 |
| 从供应商反查买家 | 公域合作案例展示原文关系类型。用户选择海关核验后，已核实买家对应到该供应商和目标品类的交易。存在同名供应商时先确认主体。 |
| 多实例与查证 | 为不同产品或市场各建一个实例，同一企业在一次运行中去重，两次运行保留各自证据。已核验线索可回查源记录，补查失败时保留原有候选。 |
| 公域动态与政策 | 输入同名企业、跨语言转载和同一政策的征求意见稿及后续生效公告，核验主体、聚合重复新闻并区分政策状态及日期。仅有媒体报道时显示待核验。模拟在线检索失败时仍可查看已有采购商及贸易证据。 |
| 零付费商业数据调用 | 普通拓客和基础报告在商业数据凭据缺失及 DeepSeek Search 无结果时，均可结束并返回对应状态。断言商业公司详情、联系方式、海关和信用供应商调用数为 0，DeepSeek 工具费用独立计算。 |
| 费用和状态 | 增强核验先复用有效证据，达到预算后返回已有结果。并发任务不会透支，重放任务不会重复计量。覆盖无匹配、证据查询失败、预算耗尽和上游扣费待核对。 |
| 线索质量 | 对首批品类和市场用相同条件对比公域优先流程与原流程。人工核验前 20 条的主体和产品相关性，记录相关线索数、公开联系方式覆盖、可查验采购信号比例、付费调用数和总成本。按有效线索数换算单位成本，另记企业级贸易证据覆盖，避免把产品匹配与交易核验合并为同一个指标。 |

接入前需通过的小样本核验包括海关覆盖范围和最新数据日期、候选列表统计字段的具体口径、产品词与 HS 同时提交时的匹配规则、多页排序稳定性、公司 ID 跨接口可用性、批量和重试扣费，以及入库和向订阅用户展示的授权范围。
