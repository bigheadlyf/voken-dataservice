## 1. 产品目标

微元 1.0 面向有企业拓客和商业研判需求的用户。用户可以自助注册并购买订阅，按目标市场、产品或行业运行拓客智能体，获取候选企业，并结合公域信息、第三方海关数据和企业信用数据研判商业机会与风险。

首版交付闭环为 **手机号加密码注册 → 领取 1,000 体验点 → 配置并运行拓客智能体 → 查看公域候选线索 → 生成可追溯的商业情报报告**。用户可以付费订阅，并在权益允许时按需核验海关交易或获取正式信用报告。服务端按授权聚合、存储和更新三类来源的数据。

本文将用户提出的能力列为首版范围。为形成可验收的闭环，本文以账号默认拥有一个工作空间、智能体由用户手动运行、商业情报以单企业分析为首版交付形态拟定需求。具体商业规则和数据供应商能力见第 8 节。

## 2. 角色与核心对象

| 角色 | 首版权限 |
| --- | --- |
| 注册用户 | 注册登录，领取初始体验点数，在体验权益内使用基础拓客和情报功能，查看余额和明细，并可购买订阅。 |
| 有效订阅用户 | 在本工作空间内，按套餐权益配置和运行智能体，查询企业和查看本空间任务结果，发起或查看情报分析。 |
| 平台运营 | 配置数据源、套餐、点数标价及操作扣点规则，查看接入及任务状态。跨工作空间访问和人工调整订阅权益或点数需授权并留痕。 |

| 对象 | 定义 |
| --- | --- |
| 工作空间 | 用户数据、智能体实例、运行结果和情报报告的隔离边界。自助注册时创建默认工作空间。 |
| 拓客智能体（数字员工） | 一份可独立保存和运行的拓客配置，包含启用状态、配置版本和运行历史。 |
| 运行任务 | 对某个实例的一次执行，保存启动时的配置版本、状态、结果和用量。 |
| 企业档案 | 汇聚同一企业的名称、地区和标识等基础信息，并关联来自不同来源的数据。 |
| 情报报告 | 基于一次分析任务生成的企业概况、机会和风险研判，以及对应的证据。 |
| 订单、订阅与权益 | 订单记录交易，订阅记录服务期限，权益定义可访问的功能、数据和用量。 |
| 点数余额及流水 | 点数归属工作空间，记录赠送、预占、扣减和释放。注册赠点发放到账号的默认工作空间。 |

## 3. 注册、订阅与计费

| 编号 | 首版需求 |
| --- | --- |
| AC-01 | 用户使用中国大陆手机号（`+86`）和密码注册及登录。注册需通过手机号验证码校验，手机号规范化后全局唯一。测试环境使用 `123456`，正式环境接入短信供应商。注册成功后建立账号和默认工作空间。忘记密码流程待确认。 |
| AC-02 | 用户可查看套餐价格、币种、计费周期和权益，并为选定套餐创建支付订单。订单保留下单时的价格、币种和权益快照，后续套餐编辑不影响已创建的订单。 |
| AC-03 | 服务端通过经验证的支付回调或主动查询确认付款，校验订单标识、金额和币种后生效。重复或乱序通知不得造成重复开通、重复延长订阅或使订单状态回退。用户可查询待支付、已支付、已关闭或退款等状态。 |
| AC-04 | 用户可查看订阅起止时间、有效状态和剩余用量，订阅到期后可自助续购。到期后仍可登录并查看订单。新发起的受限操作由服务端依据当时的订阅和权益判断，历史结果的到期访问策略待确认。 |
| AC-05 | 免费体验及付费套餐配置实例数量、可用功能和可访问的数据范围。点数余额与功能权限分别校验。并发请求不得透支点数，同一请求的重试不得重复计量。 |
| AC-06 | 新用户注册成功后，系统向其默认工作空间一次性赠送 1,000 点。同一账号在重复提交注册或重试时只发放一次。用户可查看余额和点数流水，并使用赠点执行体验权益范围内的操作。 |
| AC-07 | 后台预设人民币标价为 1,000 点对应 100 元。纳入计费的业务操作默认每次扣 1 点，可按操作配置不同的整数扣点，例如拓客运行、公域动态查询、基础情报、海关核验和正式信用报告。操作提交前展示所需点数。规则版本随请求保存，配置变更对后续提交生效。 |
| AC-08 | 有扣点要求的操作在执行前预占点数。余额不足时拒绝提交。完成时按规则结算并退回剩余预占，取消、失败或部分成功的结算按对应操作规则执行。可追溯到任务和流水。 |

## 4. 多源数据聚合与存储

| 数据源 | 首版接入范围 | 关键来源信息 |
| --- | --- | --- |
| 公域数据 | 优先从企业官网、官方登记、协会与展会目录、经销商名录、采购公告及开放统计发现和补全企业。按需实时查企业、地区和国家的新闻与政策。 | 原文链接、发布机构、发布时间、检索时间，以及可确认的事件日期或政策生效时间。 |
| 第三方海关数据 API | 按供应商实际覆盖范围接入进出口记录，支持按企业和套餐允许的贸易条件检索。 | 供应商记录标识、贸易日期，以及实际返回的企业、地区、商品或 HS 编码。 |
| 企业信用报告或 API | 接入结构化信用信息或授权报告，按企业检索可用信息。 | 报告或记录标识、供应商、出具或更新日期、可访问范围。 |

| 编号 | 首版需求 |
| --- | --- |
| DT-01 | 每类数据源至少有一个可运行的接入。服务端保存授权范围内的源记录或报告及其规范化结果，关联来源、获取时间、数据时间和处理状态。对不允许持久化的字段或文件，根据授权采用引用或限时缓存。 |
| DT-02 | 接入任务支持按来源配置刷新策略，可查看最近成功时间、失败原因和处理数量。遇到限流或暂时失败时可重试，从已确认的同步位置恢复。同一批次重复处理不得新增重复记录或覆盖较新的源版本。 |
| DT-03 | 规范化企业名称和地区，优先用来源可验证的稳定标识匹配企业。名称重合或匹配证据不足时保留待确认关系。字段冲突保留来源和时间，避免把不同企业的贸易记录或信用信息误归到同一企业。 |
| DT-04 | 服务端支持按企业名称、地区或可用标识查找企业档案，并根据权限查询关联数据。响应可区分未查到、数据未覆盖、无权访问、过期和上游暂不可用。获取状态和数据时间可供智能体及情报分析使用。 |
| DT-05 | 原始数据、规范化数据、企业关联和衍生结果保留所需的追溯关系。数据访问、展示、引用和保留期限按来源授权执行，涵盖报告和候选清单等衍生结果。 |
| DT-06 | 公域网页在线检索使用 DeepSeek Search API，重要原文按需使用 DeepSeek Fetch API 读取。用户可按企业、地区或国家，结合主题、行业或产品及时间窗口检索和刷新。系统返回带原文链接的去重结果，并区分未命中、待核验和搜索不可用。 |
| DT-07 | 公域结果须核验企业主体、适用地区和产品相关性，并标明来源类型。政策以发布机关原文作为确认状态的依据，记录可确认的文号、适用范围、发布及生效日期，区分征求意见、已发布待生效、已生效、修订或废止，以及状态待核验。 |
| DT-08 | 优先复用仍有效且获准使用的数据。已知官方开放接口和目录可直接读取，公域网页搜索统一由 DeepSeek 执行。按照独立预算限制搜索及原文读取次数，分别记录公域搜索、商业核验和订阅用量。 |

## 5. 拓客智能体（数字员工）

公域找客、按需核验、成本控制和验收用例见[《微元 1.0 拓客能力设计》](./微元1.0拓客能力设计.md)。

| 编号 | 首版需求 |
| --- | --- |
| AG-01 | 用户可在工作空间内创建和查看多个数字员工。创建时校验套餐实例额度，保存名称、目标市场和产品或行业条件，可选填企业特征和排除条件。新建后默认暂停，等待用户启动。 |
| AG-02 | 用户可编辑数字员工的运行配置。每次保存产生新版本。启动时使用当时最新的配置版本，已提交任务沿用提交时保存的配置。任务可查询排队中、运行中、取消中、成功、部分成功、失败或已取消等状态。 |
| AG-03 | 智能体默认用公域来源发现企业、核对主体、按产品和市场匹配度排序，并从官网补全公开商务联系渠道。线索标明产品或渠道匹配、公开采购信号及已有海关交易证据。区分已完成且无匹配与来源不可用造成的覆盖不足。 |
| AG-04 | 用户可查询实例的运行历史、打开某次运行的结果，并从候选企业发起情报分析。一个实例的执行异常不得阻塞其他可独立执行的实例。任务提交支持幂等处理，部分失败时保留已完成结果并标出受影响来源。 |
| AG-05 | 用户可在拓客实例启用公域信号查询，也可从单条线索手动刷新。输出可核验的企业动态、目标市场动态及相关政策提示，并说明与该线索或产品的关联。企业官网或新闻提供的商业信号使用独立证据类型。采购交易的核验仍关联对应的海关记录。 |
| AG-06 | 普通拓客的付费商业数据预算默认是 0。用户明确选择增强核验时，服务端校验订阅权益和预算，优先复用合法且有效的证据，再按范围调用海关或其他已选数据接口。公域结果少或付费预算耗尽时，交付已有结果并说明缺口。 |
| AG-07 | 用户点击启动后，数字员工设为已启用并提交一次拓客任务。同一员工同一时间最多有一次未结束的运行。重复提交同一次启动请求返回原任务。已启用表示允许手动运行，实际执行情况由任务状态显示。 |
| AG-08 | 用户可暂停数字员工。暂停时取消排队任务，运行中的任务在当前步骤结束后停止，保留已获得的结果。已经开始的外部调用按实际情况结算，释放未使用的额度。重新启动时，以最新配置创建一次新运行。上一次运行仍在取消中时，先等该次运行结束。 |
| AG-09 | 用户可删除数字员工。删除后从默认列表移除，禁止编辑及启动，并取消排队或运行中的任务。首版按软删除处理，已有运行结果和情报报告可在工作空间历史记录中按权限访问。实例计数暂按未删除的数字员工计算，暂停期间仍占用实例名额。 |

## 6. 商业情报分析

| 编号 | 首版需求 |
| --- | --- |
| BI-01 | 用户可以从候选清单或通过企业搜索选定目标，发起单企业分析。服务端返回任务状态，分析完成后保存可在本工作空间内重新打开的报告。 |
| BI-02 | 基础报告使用公域资料和已有的授权证据，涵盖企业身份、业务概况、公开风险信号和拓客机会，标明数据缺口。企业级交易和正式信用报告需进一步获取时，由用户按需选择增强核验。官方汇总贸易统计作为市场背景，并注明统计口径。 |
| BI-03 | 报告区分源数据事实和基于事实的研判。关键事实和研判依据可追溯到用户有权访问的原始来源或记录，包含适用的记录日期或获取时间。证据不足时标记为无法判断。 |
| BI-04 | 报告保存生成时间、企业标识、分析所用的来源版本或引用。后续重新分析生成新报告，并可查看历史版本。单个来源不可用时，有足够证据的部分仍可生成，并标示缺失项。 |
| BI-05 | 单企业情报报告可包含近期企业新闻、目标市场事件和与企业业务或目标品类相关的政策变化。每项标明来源、时间、已确认事实和可能影响。支持独立查询地区或国家动态，并将相关结果引用到企业报告。 |

## 7. 服务端要求与验收

### 服务端要求

- 服务端统一校验身份、工作空间和数据权益，覆盖直接接口、异步任务结果和报告页面的数据读取。凭据受控存储，认证信息、支付敏感信息和供应商密钥不得进入普通日志。
- 对支付确认、人工权益调整、数据同步、任务执行和配额变更保留可关联的审计或运行记录。运营可查询关键状态和失败原因，用户只接收与自身资源相关的信息。
- 为数据接入、拓客任务、情报任务和支付对账提供可监测的成功率、延迟、积压或异常指标。接入恢复、响应时延、任务耗时、最大并发、数据保留和恢复目标在供应商及预计用量明确后补充量化标准。

### 首版验收场景

| 场景 | 通过条件 |
| --- | --- |
| 自助开通 | 新用户完成注册并支付后可查看有效订阅及套餐权益。模拟重复支付通知和乱序通知，订阅只生效一次，订单状态正确。覆盖支付失败、到期和续购。 |
| 隔离与额度 | 两个账号尝试读取对方的实例、任务结果、订单或报告，服务端拒绝访问。两个并发请求同时消耗最后一份额度时，成功计量最多一次。 |
| 三类数据入库 | 每类来源完成至少一次接入，授权数据可持久化并按企业查询。重放同批数据无重复，源记录和更新时间可追溯，同名不同企业的记录保持分离。 |
| 接入异常 | 模拟一类供应商限流或中断，其他来源可继续处理。故障恢复后同步可续跑，无重复入库。查询结果可识别受影响的数据及其状态。 |
| 多实例拓客 | 同一工作空间建立两个配置不同的实例并运行，各自保存配置版本、任务状态和结果。用户可查看命中原因及可访问的证据，其中一个实例失败不影响另一个。 |
| 数字员工生命周期 | 新建后显示暂停。启动后只产生一次任务。排队或运行时修改配置，当前任务沿用原版本，下次运行使用新版本。暂停或删除能取消排队任务，运行中的任务停止后续步骤并保留已有结果。删除后列表隐藏、实例名额释放、历史可查。使用另一工作空间的账号尝试操作时，服务端拒绝。 |
| 情报分析 | 从候选企业发起分析并打开已保存的报告。关键结论可追溯，缺失或冲突的数据有相应说明，重新分析保留历史报告。 |
| 公域实时搜索 | 分别按企业、地区和国家检索。用含同名企业、转载新闻、旧闻重发、政策征求意见稿和生效公告的样本校验归属、去重、日期和政策状态。模拟公域搜索失败，既有海关线索仍可查看，页面能区分复用的历史结果及当前检索状态。 |
| 成本控制 | 普通拓客与基础报告在零付费商业数据调用下完成。公域结果不足时说明覆盖缺口。按需核验优先复用有效证据，对同一工作空间的并发任务校验预算上限，并记录实际供应商消耗。 |
| 免费体验全链路 | 使用新手机号和密码注册，确认余额 1,000 点，启动数字员工、查看公域线索并生成基础报告。核对提交前报价、任务执行与点数流水。使用首批三条真实输入验收。 |

## 8. 待确认的产品决策

| 优先级 | 决策 | 需要确认的内容 |
| --- | --- | --- |
| P0 | 首批市场和客户 | 优先服务的行业、国家或地区，首批用户最常用的拓客筛选条件。 |
| P0 | 数据供应商与授权 | 每类数据源的具体名单、试用或生产凭据、覆盖范围、刷新频率、调用额度，以及入库、展示、引用和保留权限。 |
| P0 | 公域检索范围与用量 | 首批覆盖的国家和地区、语言、政策主题和官方来源，DeepSeek 接入凭据、单次检索预算、缓存时效和引用权限。 |
| P0 | 账号与空间 | 正式短信供应商与找回密码方式，体验防重复领取规则，是否在 1.0 支持企业邀请和多人协作。 |
| P0 | 支付与订阅规则 | 支付渠道、币种、价格、周期，自动续费、取消、退款及其对权益的影响，到期时在途任务和历史报告的访问策略。 |
