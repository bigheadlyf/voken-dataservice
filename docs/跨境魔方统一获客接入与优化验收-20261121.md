验收日期：2026-11-21。基于现有 TradeWind 实测样本、跨境魔方官方接口定义、真实供应商返回及本地工作台操作。代码与本地服务已更新，未部署生产环境。

## 已交付能力

- 新增“企业与联系人”入口：按企业、官网、产品、国家查企业，选择企业后查人员，支持职位条件、邮箱库存条件及逐页查询。
- 企业、人员使用独立命名空间；只解锁用户选中的单个主体。联系人结果保留供应商有效性、来源、电话类型和 WhatsApp 标记，过滤掩码与格式模板邮箱，不将库存数当作实际邮箱数。
- 产品、HS、日期及路线条件可直接查海关，不再要求预先知道买家公司；明确确认后逐页查询，保留原币种、数量单位及运输路线。
- 联系方式分组持久化到 CRM，保存前核对企业归属。空主联系方式优先采用有效的返回邮箱，已有值不覆盖。客户详情可查看分组和来源任务。
- 新增最多 5 家的真实预览，不创建员工、周期任务或外联；支持多个参考网站、排除域名、符合/不符合/撤销反馈。不符合反馈仅影响同画像后续任务，原始结果不改写。
- 新增“增强：优先补联系方式”：公域筛选后最多检查前两家；名称规范化后同名、同国家且唯一才自动解锁企业联系方式；歧义保留待核实。保留原增强档预算和现有海关优先模式。
- 汇总分别计数企业、有邮箱企业、有引用企业与有日期当前需求；避免用联系人行数或历史交易量代替可触达企业和当前采购需求。
- 修复客户详情反复加载的问题；补齐跨账户界面状态清理、费用提示、空结果与歧义提示。

## 费用、重试及权限

官方公开接口：`/agent/search/company/list`、`/agent/search/person/list`、`/agent/search/contact/batch`。本次账号接口价格返回：企业/人员每页最多 20 条，1.5 元；联系人每主体 0.5 元；海关明细每页 1.5 元。实际计价以供应商当时合同及接口返回为准。

本次真实调用的金额回传为 0，`billing_mode=PLAN`，同时存在请求、记录和解锁配额消耗。因此页面同时显示金额和配额，不称为免费。预算控制按至少配置单价占用执行预算，避免金额回传 0 导致无限追加调用；用户数据点数仍按现有明确金额规则结算，平台费独立。

付费请求须 `confirm_paid: true` 和 `Idempotency-Key`；同 key 不同请求返回 409。同工作空间相同请求 24 小时优先复用；联系人按主体命名空间与 ID 复用，避免元数据变化造成重复解锁。分页只能引用本工作空间上一页任务，沿用原筛选；不接受外部任意游标。公司、人员、CRM 和反馈均验证工作空间归属。

## API 使用

统一前缀：`/api/v1/workspaces/{workspace_id}`，Bearer 登录。付费查询异步返回任务，通过现有 jobs 接口读取结果和供应商日志。

| 方法与路径 | 用途 |
| --- | --- |
| POST `/directory/searches` | 企业/人员查询；下一页只传 continuation_job_id 与 confirm_paid |
| POST `/directory/contacts` | 传查询 job_id、选定 record_id 与 confirm_paid，解锁一个主体 |
| POST `/directory/trades` | 产品/HS/日期/国家海关查询及逐页继续 |
| POST `/directory/save-company` | 从自己的企业结果保存待核实客户 |
| POST `/directory/saved-contacts` | 核对企业后保存联系人分组 |
| GET `/directory/saved-contacts/{prospect_id}` | 查看客户联系人分组 |
| POST `/discovery/preview` | 使用现有画像字段提交基础公域预览 |
| POST `/discovery/feedback` | 保存 fit / not_fit / unreviewed |
| GET `/discovery/feedback/{job_id}` | 查看反馈 |

企业查询示例：

```json
{"kind":"company","company_name":"Marmetal","country":"US","require_email":true,"confirm_paid":true}
```

员工运行的联系方式优先模式：`POST /agents/{agent_id}/runs`，请求体：

```json
{"acquisition_tier":"enhanced","enhancement_goal":"contacts","confirm_paid":true}
```

省略 enhancement_goal 仍按原有 trade 模式运行。公域预览仍消耗基础平台点数，不调用付费数据源。

## 验证与上线状态

- 完整回归 129 项通过，耗时 99.798 秒；其后名称标点规范化的小修改再跑获客测试 11 项通过。UI 检查、JavaScript 语法、OpenAPI、迁移与 MySQL 离线迁移生成检查通过。
- 真实链路已验证企业查询 → 单主体解锁 → 人员查询 → CRM 保存，以及海关两页与公域预览反馈撤销；未发送邮件、短信或 WhatsApp。
- 联系方式优先自动链路已通过带供应商形状数据的测试；真实首次运行发现名称标点匹配问题并修复。随后真实重试因选中来源不支持完整企业名称而返回 0 条，保持证据校验、未追加付费调用。**尚未证明该自动链路在真实公域发现中稳定补齐邮箱**，不能用手动链路成功代替这一验收。
- 当前本地入口：[AI 拓客工作台](http://127.0.0.1:18084/app)。生产上线前执行 `python -m alembic upgrade head` 并重启服务；新增迁移 `0014_directory_contacts_feedback.py`。本地数据库已备份；未修改生产环境。

## 剩余差距

个人邮箱覆盖仍取决于供应商数据；本次两个关键人员解锁为空。公开搜索对来源选择和完整企业名称的稳定性仍不足。海关结果需要继续识别物流公司与真实采购主体。尚未新增独立邮箱投递验证、真实外联/回复闭环、自动 WhatsApp 触达或 TradeWind 同等规模的数据源覆盖。后续应按相同画像、相同日期范围，分别衡量企业命中率、可用邮箱覆盖率、人员匹配率、物流噪声和单位可触达企业成本，而非只比展示行数。

脱敏结果摘要见 [统一获客实测数据](./benchmarks/upkuajing-directory-20261121.json)。供应商原始响应、账号及任务标识保留在本地 `.local`，未纳入该摘要。
