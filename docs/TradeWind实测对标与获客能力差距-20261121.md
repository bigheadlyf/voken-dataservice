# TradeWind 实测对标与获客能力差距

核对日期：2026-11-21，香港时间。对象：已登录的 TradeWind 七天试用账号、本仓库及本地真实服务 `http://127.0.0.1:18084`。

## 结论

微元已经覆盖企业画像、多语言发现、证据、基础调研、CRM、周期计划和人工审阅开发信这条业务链。当前最明显的差距是**从相关企业继续找到可用的人、岗位与联系方式**，其次是可分页的贸易数据产品、展会名录和外联回流。继续增加自然语言聊天入口，不能替代这几项数据能力。

本次同画像任务中，微元返回 8 家独立企业、0 个邮箱；TradeWind 被提前停止的任务返回 9 条联系人记录，但只有 4 家独立企业，其中 2 家有邮箱。不能把“8 家企业”和“9 个联系人”直接比较为获客有效率。双方都没有验证出当前明确采购需求或成交效果。

最快补齐数据的候选路线是：保留微元的业务编排与证据体系，将 TradeWind 的官方企业/联系人/邮箱验证 API 作为可选数据供应商进行小样本采购评估。另一条路线是分别接入联系人数据库与邮箱验证商，维护成本更高。TradeWind 的 API 官网明确宣传可嵌入 SaaS，但实际转售、存储、缓存和再分发权仍需按正式协议确认。

## 实测范围与限制

- 浏览器只通过可见产品流程查询，没有提取浏览器令牌或调用未公开的内部接口。
- 创建了 `对标实测-美国镍合金经销商-20261121`，选择“暂不发送”。任务已停止，最终任务列表获取人数为 9、无下次执行日期。统计页邮件 0、短信 0、已触达联系方式 0。
- 该试用账号只有一次 AI 企业拓客任务。正式任务没有跑到自然结束，**9 条是观察截面，不是 TradeWind 的完整产能上限**。停止提示说明未发出的线索可能在 5 天后按 25% 计入其有效拓客用量，应以账号账单为准。
- 微元执行的是基础档任务，目标 10 家，按现有调用上限完成；TradeWind 使用自身扩词和多渠道流程。两者执行范围、耗时与计费口径不相同，本次属于产品/样本核查，不是受控性能实验。
- 招投标商机点击后进入升级页；客户背调提示当前套餐不支持；AI CRM 高级列表禁用；展会全量名录需另行解锁。相关质量没有被实测。
- “100+ 渠道”“60 亿海关数据”“41% 无效数据筛除”“AI 验证可安全发送”等是产品页面陈述，本次未独立验证其统计或验证方法。

## 4. 本轮已落实的改动

1. **企业国家不再由查询条件冒充。** 兼容实际响应 `countryCode` 与旧 `countryInfo.code_iso2`；明确返回其他国家的记录剔除，缺国家保留 null，单独标注 `requested_buyer_country` 与 `country_verification`。
2. **保留贸易原始信息。** 兼容 `productHscode`，保留数量/单位、重量/单位、金额/币种、价格、两端国家、原产/抵运国、港口与上游交易标识。不把空币种补成 USD，不把 CARTONS 换成 PIECES，不把 HS 请求值写成返回事实。
3. **过滤联系人污染。** 招聘入口、招聘邮箱、CourtListener 法律文书邮箱不作为拓客联系候选；明确只有摘要/链接/抓取失败的来源不进入正文邮箱候选；常见 `FLast` 等格式占位符剔除。原始来源仍保留以便核查。
4. **区分联系入口。** 增加通用商务、采购类待核实、质量/客服、未知角色标记；统一说明未检测可投递性。角色是邮箱前缀的保守分类，不是已验证的人物岗位。
5. **已知官网优先查联系入口。** CRM 研究传入客户明确保存的 website，优先添加限定该域名的 contact/email 查询，仍受既有调用上限约束；不从第三方目录猜官网。
6. **分离商品词与角色词。** 规划提示明确海关商品只能填如 `nickel alloy`，不得拼入 distributor/importer 等角色。该项是提示约束，尚不是报关词典或确定性语义校验。
7. 工作台展示上述贸易单位/路线/缺失值与联系人角色，OpenAPI 同步说明。

真实旧结果离线重放：High Performance Alloys 原 6 个邮箱候选，剔除法院 2 个和招聘 1 个，剩 3 个（未知个人角色、质量、通用销售各 1）。Marmetal 的格式占位符剔除后为 0；不以错误邮箱凑数。过滤规则不能排除所有不相关企业邮箱，采用前仍须核对主体。

这些是本地代码改动，未部署生产、未更新已启动进程中的 Python 模块；不会改写历史任务快照。新增真实任务的结果属于修复前基线，离线重放属于修复验证，二者分开记录。

## 5. 补齐顺序与验收

### 第一优先：企业 → 人 → 可用联系方式

增加独立 Contact 与 ContactEvidence 实体，不再用企业上的一个 contact 文本承载所有联系人。至少包含姓名、原始职位、部门/职级（可未知）、公司关系、来源、观察时间、邮箱/电话/社媒、验证状态与验证时间。前端分别统计独立公司数、有邮箱公司数、独立联系人数、采购岗位数、验证通过邮箱数。

采用“官网公开入口 → 一个授权联系人供应商 → 独立邮箱验证”的小范围瀑布流，命中足够即停。未命中、通用邮箱、人员邮箱、岗位不匹配、主体不明、邮箱格式示例都分别记录。空结果不得显示为补全成功率提升。

验收先使用本次四家 TradeWind 企业及微元八家企业，逐企业检查同一域名与公司主体；对比补全前后可用邮箱、真实岗位和成本，不预设供应商一定能返回采购负责人。把 Marmetal 四位销售岗位和 ImageStar 的零采购岗位作为反例。

### 第二优先：贸易数据产品化

先补当前上游的游标分页、实际路由/国家、原始单位和覆盖期；按商品条件对同一家买家检查近期交易，提供供方、频次与时间趋势。将现金费用、套餐请求配额和记录配额分别预算；`apiCost=0` 不代表套餐记录没有消耗。此配额预算目前仍是未落实缺口。

用 food pan 中的物流主体、玩具、混装单位作为反例。不能以贸易总行数或模糊词匹配比例做买家相关性评分。别名/品牌主体合并需证据，不能只按同名合并。

### 第三优先：名录和执行前预览

先把用户有权使用的展会 CSV/XLSX/PDF 做字段映射、预览、来源与年份记录，再评估付费展会库。支持结构化排除域名与多参考企业、执行前样本点赞/点踩，并保留反馈原因供下一轮筛选。

### 第四优先：外联回流与规模化
