# 联系人接口对照与 LLM / OSINT 优化验收

2026-11-21，本地真实接口、真实模型及公开来源验收。未部署生产，未发送外部消息。原始响应、账号与任务标识保留在 `.local`；本文与结果摘要不包含密钥。

## 两个联系人接口实测

对 Marmetal Industries LLC（企业）、William Tomaszewski 和 Candice Stover（人物）各调用两个接口，共 6 次真实请求，同一账号、相邻时间、相同主体 ID。

| 项目 | `/search/contact` | `/agent/search/contact/batch` |
| --- | --- | --- |
| 地址 | `https://openapi.upkuajing.com/search/contact` | `https://openapi.upkuajing.com/agent/search/contact/batch` |
| POST 参数 | `bus_id` 单个 ID、`bus_type` | `bus_ids` 列表、`bus_type` |
| 主体类型 | 1 企业、2 人物 | 1 企业、2 人物 |
| 响应形状 | `data` 直接包含四类渠道 | `data.list[]` 包含主体 ID、类型及 `contact_data` |
| Marmetal 企业 | 1 邮箱、1 电话、2 网站值、1 社媒 | 完全相同 |
| 两位人物 | 均为空 | 均为空 |
| 本次计费 | PLAN，apiCost=0 | PLAN，apiCost=0 |
| 企业请求回传用量 | request=1、records=5、unlocks=5 | 相同 |
| 每位人物请求用量 | request=1、records=0、unlocks=0 | 相同 |

不仅数量相同，三个主体的完整渠道对象（包括返回的有效性等字段）都相同。企业公共邮箱为 `sales@marmetal.com`。两个网站值是同域名变体，不能算两家企业；五个值/五个解锁配额单位也不能解释为五位联系人。

结论：本次样本中切换接口没有增加邮箱覆盖。继续使用已接入的 batch 接口、每次只解锁选定主体，保留应用层幂等与缓存；没有添加自动双接口重试，避免重复消耗配额。这不能证明两条接口在所有账号、主体、数据更新时点或余额计费合同下都完全相同。本次套餐金额回传 0 仍消耗配额。

出处：[开发者中心单主体文档](https://developer.upkuajing.com/global/2005/)、[Upkuajing GitHub 批量调用脚本](https://github.com/Upkuajing/upkuajing-global-company-people-search/blob/master/scripts/get_contact.py)、[字段与有效性说明](https://github.com/Upkuajing/upkuajing-global-company-people-search/blob/master/references/contact-api.md)。脱敏对照：[JSON 证据](./benchmarks/contact-endpoint-comparison-20261121.json)。可重复运行脚本 `scripts/compare-contact-endpoints.py --live` 会真实消耗接口用量，非默认自动任务。

## LLM 判断链路的实际改动

1. 规划按画像选择工业目录、协会、官方采购与企业官网；目录用于发现候选，再核对业务和公开联系入口。将 Thomasnet 等明确目录按目录处理，避免优先级被误当作官网。
2. 搜索返回正文先保留在任务内的候选池，模型上下文仍受正文数量上限约束。候选的完整名称不被当前来源支持时，最多换入两份已经取得、含完整名称的正文，替换无关正文；不为此增加搜索、抓取或联系人解锁。
3. 先提取，再独立复核最多 10 个候选。复核使用现有 analysis 场景模型配置，仅提供正文含完整企业名的来源，分别判断角色、产品、市场，要求逐字原句。不支持的判断回到 unknown；物流公司、角色/产品/市场不符须有原句才可排除，排除记录保留供查看。
4. 模型可重选已有来源，不能改企业名或凭空建立简称/法律名称关系。换源后清空原联系方式、需求和截止日期，防止跨来源转移事实。身份名称与原句仍由代码校验，模型分数不能绕过。
5. 页面展示 AI 判断、原句、排除原因和未核实状态。模型失败保留原有确定性校验结果，不制造线索。

另修复高级模型默认值：真实 API 对 `deepseek-pro` 返回 HTTP 400，提示支持 `deepseek-v4-pro`。默认配置与示例已改正，显式 `LLM_ANALYSIS_MODEL` 等覆盖仍有效。[DeepSeek 官方模型列表](https://api-docs.deepseek.com/quick_start/pricing/)支持此次修正。二次复核比原链路增加至多一次模型调用；记录模型与 token 用量，不将模型费用当成零。

### 真实验收边界

两次新公域预览均因模型仍选用只出现简称的官网页面而返回 0 条；没有放宽完整名称校验。这暴露了仅增加提示词、仍使用宽上下文及效率模型的不足。

随后固定使用第二次任务已经取得的 5 份正文，改为通过完整名称筛选后的复核上下文，并实际调用 `deepseek-v4-pro`：原提取结果因选错来源可交付 0 条，复核重新选择含完整名称的公开目录原文后可交付 1 条。该次只有 1 个模型请求、2,659 tokens，新增搜索和联系人请求均为 0。

返回的 Marmetal 候选角色为 fit，产品及国家为 unknown，联系方式为空。它是有出处、仍需核实的候选，不是已验证美国镍基合金买家；也没有新增个人邮箱。该结果是**固定真实证据重放 + 实时模型调用**，不是修改后的完整线上发现链路成功率，不能外推整体准确率。自动化测试另覆盖物流排除、伪造原句、错误企业、国家缺依据、重复决定、模型失败和正文数量限制。

## OSINT 研究与接入

[awesome-osint](https://github.com/jivoi/awesome-osint) 是工具/服务索引，包含商业服务与公开网页，并不是全部都可直接商用重用的数据集。本次优先筛选能帮助企业发现、角色核对、公开商务联系和采购证据的来源；下面区分已接入、实测可读与尚未接入，不以来源数量代替数据覆盖率。

| 来源 | 对获客的贡献 | 本次状态与限制 |
| --- | --- | --- |
| Find a Tender | 英国买方、招标/中标阶段、公开采购联系入口 | **新增原生 OCDS 接入**；真实扫描 100 条，construction 匹配 9 条、展示 5 条。按更新时间窗口取一页，再本地匹配词，不是全库搜索 |
| Contracts Finder | 英国公共买方、合同历史、公开采购邮箱 | **新增原生 OCDS 接入**；真实扫描 100 条，laptops 匹配 1 条，明确为历史中标 |
| Thomasnet | 北美工业产品、能力、分销商/制造商分类 | **新增限站搜索入口**，非全库 API；卖方或渠道记录不证明当前采购 |
| Kompass / Europages | 行业与地域企业发现、交叉核对 | **新增两个限站搜索入口**；未取得付费联系人库或全库重售权限 |
| MSCI / NAW | 金属服务中心、批发分销生态与公开协会页面 | **新增合并限站入口**；部分目录需要登录，仅查询公开可索引部分 |
| OpenCorporates | 公司登记号、司法辖区和同名主体消歧 | **新增限站入口**；官方原生 API 要密钥与适用许可，未接入原生 API |
| GLEIF / Companies House | 法律实体参考 | 已有接入；LEI 覆盖不了所有中小企业，英国原生 API 仍需密钥；无当前采购证明 |
| TED / 世界银行 | 公开采购机构、公告及期限核对 | 已有原生接入；仍区分公告、有效期限、资格和最终买方 |
| SEC EDGAR | 上市公司业务、分部与公开披露 | 已有限站入口；美国上市/申报主体范围，不是全体企业联系人库 |
| OpenStreetMap / Overpass | 线下店铺、地址、部分公开企业网站与联系标签 | 已研究官方接口，未接入；适合门店类画像。商业持续使用需适当服务部署/方案，不能把社区公共端点当无限商用后台 |
| Common Crawl | 找遗漏的官网页面、历史业务页和域名线索 | 索引目录 HTTP 200；未接入应用。最新索引为 2026-43，历史抓取不能证明当前邮箱/任职，需按域名、路径、日期收窄 |
| GDELT | 扩产、新厂、项目、任命等新闻信号 | 本机真实请求 HTTP 429；未接入。新闻只能作为核验触发，不等于已确认采购 |
| Wikidata | 企业别名、官网、位置等实体参考 | 本机真实请求 HTTP 403；未接入，不绕过访问限制，众包记录也需交叉核对 |
| OpenAlex | 科研机构与研究方向、技术市场线索 | 已研究官方文档，未接入；偏科研，不能将作者联系入口当作工业采购负责人 |
| CPSC 召回 API | 品牌、制造/进口主体与产品风险线索 | 本机 HTTP 200，但关键词结果含无关项；未新增原生接入，保留已有官方限站查询。召回不是采购需求 |
| OpenSanctions | 同名排查与风险线索 | 研究官方许可，未接入；不是获客邮箱源，商业数据使用须按其许可方案处理 |
| OpenLeads | 可参考按画像路由、团队页提取及邮箱证据标签 | 研究源码仓库说明，未安装、未复制代码。项目为 AGPL-3.0，不能直接视作无条件的闭源 SaaS 组件；其 pattern/guessed 地址也不能计作本系统已取得邮箱 |

新增来源中，两项是原生 API 升级、五项是限站检索入口；来源目录现在共 6 项原生、16 项限站，共 22 项。配置齐备不等于连通性和覆盖保证。并未购买或接入 22 个完整数据库。

英国原生接口保留 release/ocid、公告阶段、原金额/币种、投标截止及来源归属；只从明确的单一 buyer party 取邮箱，绝不把中标供应商邮箱归给买方。国家仅来自主体地址，英国发布渠道不自动作为主体所在地。中标、完成、取消、过期分别显示；合同期限不当作投标截止。零结果显示“本页未匹配”，并披露扫描数、匹配数和窗口。未自动跟随分页链接。

研究的主要原始出处：[英国政府 Open Contracting](https://www.gov.uk/government/publications/open-contracting)、[Find a Tender API](https://www.find-tender.service.gov.uk/apidocumentation/1.0/GET-ocdsReleasePackages)、[OpenCorporates API](https://api.opencorporates.com/documentation/API-Reference)、[Overpass 使用说明](https://wiki.openstreetmap.org/wiki/Overpass_API)、[Common Crawl 索引](https://index.commoncrawl.org/)、[OpenLeads](https://github.com/Samyrrrrrr990/openleads)、[OpenSanctions 许可](https://www.opensanctions.org/licensing/)、[MSCI](https://www.msci.org/)、[NAW](https://www.naw.org/)。
