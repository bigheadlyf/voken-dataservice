# 全球公开情报源目录与接入策略

核查日期：2026-11-20；世界银行原生接口补充于 2026-11-21。面向中小外贸团队，以低现金成本获取可追溯情报。这里的“数据源”包括原生接口和限定官方网站的检索入口，两种接入模式明确区分；没有把链接目录包装成已经下载的全球企业数据库。

## 已接入的来源

工作台“全球情报源”对应 `GET /sources`；提交 `POST /sources/searches` 后在任务中查看结果。以下路径均使用工作空间前缀并鉴权。

“限站搜索”会在查询中加入官方域名，并在接收搜索结果时再次验证域名。即使上游搜索返回其他站点，系统也不会把它混进该来源结果。该方式仍受搜索索引、动态页面与正文获取能力限制，不能保证官网所有记录都可检索。

“原生接口无单次数据费”与“平台免费”不同。官方接口任务仍有平台点数、基础设施和运维成本。限站搜索还使用既有搜索与模型服务。

公域采购线索另保留时效分类。历史信号和无日期信号可以留作后续核验，但不计入正文支持未来截止日期的数量；即使未来截止日期得到原句支持，仍不能跳过标段、资格和最新更正检查。

## 这些来源如何进入获客流程

1. **搜索前**：用我方产品、目标客户角色和市场决定找经销商、制造商、品牌还是公共采购方，而不是只搜索产品名称。
2. **发现时**：一般客户使用公开搜索。若目标是公共采购，可勾选 TED，在同一次任务加入近 90 天的官方公告候选，默认不打开、不付费购买海关信息。
3. **主体核对**：将已有公司名交给 GLEIF 或 Companies House。核对名字、国家、标识和地址，不仅看同名。
4. **补全与筛选**：先查官网联系页面、真实正文和来源。缺少商务联系方式时，再决定是否用跨境魔方付费补全。
5. **沟通前**：确认目标企业、产品相关性、联系人归属和联系理由。公开邮箱只表示页面上出现过，不等于已验证投递或该人有采购权限。
6. **跟进后**：把明确回复、拒绝和成交记录回 CRM。一次打开或某条历史采购记录不能替代这些反馈。

官方记录可以人工选择保存为待核实客户；含多个买方且主体不清的公告不会自动保存为一个虚构公司。当前不依赖把每个来源的全库先拷贝到本地来启动服务。

## 为什么要做数据边界控制

### 注册主体不同于目标买家

实际使用宽泛名称 `Siemens` 查询 GLEIF 时，结果出现同名基金。即使有 LEI，这些主体也不一定是需要采购工业产品的公司。因此默认增加一般企业类别筛选，明确保留类别选择；用户仍应输入尽可能准确的法律名称并核对国家。

同样，LEI 登记状态过期与法律实体注销并非同一字段，不能混写为“公司倒闭”。注册地址、经营地址与联系地址也不能无证据替换。

### 采购入口的 ACTIVE 不足以证明现在开放

一次 TED 真实样例查询中，单用 `scope=ACTIVE` 返回过 2017 年记录。本实现增加明确的 `publication-date` 条件、日期倒序，并在接收端再次检查发布时间；不因上游标签就跳过核验。

当前公告记录带 `procurement_notice` 类型，状态为“截止日期与资格待核实”。多标段的日期列表不一定与用户目标产品逐项对应，因此不直接用“最晚日期还没到”来宣称该产品可投标。实际用户还应看采购文件、最新更正和参与条件。

### 搜索到公开数据不同于可重售整个数据库

每个来源保留官方链接与使用说明。GLEIF 的 LEI 参考数据明确采用 CC0，其他来源要按自身条款、署名要求、接口额度和再分发范围处理。此系统提供小范围查询与证据整理，不绕过登录、验证码、付费墙或接口限制。

## 接口与配置

```http
POST /api/v1/workspaces/{workspace_id}/sources/searches
Authorization: Bearer <token>
Idempotency-Key: <唯一操作键>
Content-Type: application/json

{"source_id":"gleif","query":"Siemens AG","country":"DE","limit":10,"entity_category":"GENERAL"}
```

```http
POST /api/v1/workspaces/{workspace_id}/sources/searches
Authorization: Bearer <token>
Idempotency-Key: <另一唯一操作键>
Content-Type: application/json

{"source_id":"ted","query":"lighting","country":"DE","since_days":90,"limit":10}
```

返回任务后用 `GET /jobs/{id}` 查看 `result.source_lookup`。`total_reported` 是上游报告数量，`records` 只是本次一页，不应当作已经抓取了全部记录。当前每页最多 20 条，不自动分页。

配置 `COMPANIES_HOUSE_API_KEY` 启用英国登记。`PUBLIC_SOURCE_DAILY_CALL_LIMIT` 默认 100，0 禁用新增原生官方查询。结果复用现有的工作空间缓存。密钥只在服务器环境保存，不进入模型输入、任务结果或浏览器。

Agent 配置 `public_sources:["ted"]` 可把 TED 公告纳入一次普通发现任务；默认是空列表。目标国家由规划器解析为 ISO 二字码，无法可靠解析时会提示缺口，不悄悄把全球公告当作该国结果。周期更新若启用这一选项，也仍是基础档，受同一官方源调用上限控制。

公开邮箱查证使用 `POST /crm/prospects/{id}/research`。邮箱只能从上游实际返回的正文中直接提取；用户核对主体后使用 `POST /crm/prospects/{id}/apply-contact` 采用。它不会猜测姓名组合邮箱，不自动覆盖客户联系方式，也不代表邮箱可投递。

## 当前实测和验证

- GLEIF 官方接口返回成功，验证了法律名称、实体状态、登记状态和分页字段；浏览器完成来源查询与原始记录展示。
- TED 原生适配器取回德国照明公告样例，发布时间为 2026-11-19；本次只取两条，未声称覆盖全部机会。
- 公开搜索小样本的第二轮改进后，3 家德国照明候选中有 2 家获得正文原句支持，1 家仍只有摘要。没有获得可靠联系方式，不能作为已联系客户交付。
- 新增测试覆盖官方字段适配、过期公告过滤、多买方歧义、密钥不回传、缓存、租户隔离、每日上限和限站域名二次校验。

以上证明接入与边界处理可工作，不是对所有国家、产品或数据源做过准确率审计。完整功能、部署约定与限制见[工作台运行手册](./AI拓客工作台运行手册.md)。

### 世界银行原生接口补充

当前目录共 17 个入口：4 个原生接口（英国登记需密钥）与 13 个限站搜索。世界银行原生查询使用 `source_id:"worldbank_notices"`，例如：

```json
{"source_id":"worldbank_notices","query":"solar","since_days":90,"limit":10}
```

不传 `country`；传国家过滤会在扣点前返回 422，避免静默忽略条件。接口只请求一页，并在本地再次校验 Published、Invitation for Bids 和发布日期。保留截止日期与时间；没有可靠时区时不据此声称仍可投标。项目国家在 `details.project_country`，`country` 不伪造 ISO 代码。

`entity_name` 仅取公开 `contact_organization`，缺失时不拿项目名称代替。`details.published_procurement_email` 只是公告公开邮箱，不自动写入 CRM 联系方式。保存后可在档案点击“已核对，采用公告邮箱”，使用原任务与记录校验后人工采用，保留出处，不再发起搜索或模型调用。保存后仍是待核实客户。截止日期已过的公告保留为历史情报并标记 expired。

2026-11-21 实测一页三条公开投标邀请成功，包含公告、截止、项目国家及联系机构字段。样本也显示“solar”可命中项目背景而非所需货物，不能把上游检索总数当成匹配买家数量。新增适配测试覆盖中标/取消/过旧公告过滤、截止状态和缺失采购主体。
